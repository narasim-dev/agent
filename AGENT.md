## Главное предназначение

**Narasim** — универсальная многопользовательская платформа для создания и запуска дочерних сайтов и программных проектов. Главная цель — дать каждому проекту отдельное окружение, в котором он может самостоятельно собираться и работать. Целевая схема — внешний Docker-in-Docker (DinD) контейнер на проект и собственный `docker-compose.yml` внутри него. Состав сервисов и процедуры установки определяет сам дочерний проект; основной сервис остаётся универсальным. Рабочий образец — `storage/projects/cmp46pi4f000l8hutv0gd8461/projects/modx-test/`.

Кодовая база основана на KMS-Agent — движке автономных ИИ-агентов с собственной идентичностью и базой знаний. Поэтому в репозитории присутствуют возможности агента и веб-платформы, которые используются и развиваются Narasim. Перед работой с запуском проектов читать `project/tasks/README.md` и актуальную задачу; старые резолверы могут отражать предыдущие архитектурные попытки и не обязательно задают целевой процесс.

## Технологии и возможности

- TypeScript, Next.js 16 (Pages Router), React 19, styled-components.
- Сервер Express 5, GraphQL на Apollo Server и Pothos, PostgreSQL через Prisma 6.
- Автоматизация через n8n: сценарии описываются в TypeScript и импортируются при запуске; собственные узлы включают AgentOrchestrator.
- Помимо общения с агентами, есть база знаний, задачи и журналы работы, публикации, пользователи, авторизация, баланс и транзакции. Отдельные подсистемы отвечают за LLM, генерацию изображений и 3D-мир.
- Инфраструктура: Docker Compose, Traefik, почтовый сервер и опциональный llama.cpp.

## Основные каталоги

- `src/pages/` — маршруты Next.js; `src/components/`, `src/ui-kit/`, `src/theme/` — интерфейс; `src/gql/` — клиентская работа с GraphQL и генерация типов.
- `server/index.ts` — точка входа: запуск GraphQL, подключение n8n, проксирование API и запуск Next.js.
- `server/schema/`, `server/graphqlServer/` — GraphQL-схема и сервер; `server/llm/` — клиент языковых моделей.
- `server/n8n/` — интеграция, начальная настройка, сценарии и собственные узлы n8n.
- `prisma/` — схема данных, миграции и начальное заполнение БД.
- `docker/` — конфигурация инфраструктуры; `wiki/` — подробная документация; `project/` — задачи и релизы.

## Основные команды

- `npm run dev` — разработка; `npm run dev:n8n` — разработка с n8n.
- `npm run generate` — генерация Prisma Client и GraphQL-типов; `npm run build:custom-nodes` — сборка узлов n8n.
- `npm run build` / `npm start` — сборка / запуск production-версии.
- `npm run types`, `npm run lint`, `npm test` — проверка типов, стиля и тесты; `npm run test:api` и `npm run e2e` — API- и браузерные тесты.

## Ориентиры для работы

Начинать уточнение архитектуры с `README.md` и `wiki/README.md`, актуальные команды и зависимости сверять с `package.json`. Например, README упоминает Express 4, но в зависимостях уже Express 5. Настройки окружения описаны в `.env.example` и документации; учётные данные — в `credentials/README.md`. Команда `npm run clean` удаляет `dist/`, `.next/` и `.n8n/`, а `npm run build` вызывает её автоматически.

Обзор выполнен поверхностно по документации, структуре, зависимостям, точке входа сервера и схеме БД; работоспособность подсистем не проверялась.
